# Job Hunter AI — перенос на бесплатный Oracle Cloud Always Free

Файлы для запуска: `Dockerfile`, `docker-compose.yml`, `.env.example`.
Важно: это готовая конфигурация для переноса, а **не** уже запущенный Oracle-сервер.

## 1. Бесплатный сервер

1. Зарегистрируйтесь на https://www.oracle.com/cloud/free/ (регистрация и проверка карты выполняются самим владельцем).
2. Откройте Compute → Instances → Create instance.
3. Выберите Ubuntu 24.04 ARM64 и **VM.Standard.A1.Flex** с маркировкой **Always Free Eligible**. Не превышайте актуальный бесплатный лимит **2 OCPU и 12 GB RAM**, загрузочный диск 50 GB в домашнем регионе Oracle.
4. Добавьте **публичный** SSH-ключ с компьютера. Приватный ключ, пароли, куки и токен Telegram не отправляйте в чат.
5. Запишите публичный IP. Для бота через Telegram polling входящие HTTP-порты не нужны.

Бесплатный ARM-сервер может быть недоступен в выбранном регионе. Oracle также оставляет за собой возможность изымать простаивающие бесплатные VM.

## 2. Подключение и установка Docker

В Windows PowerShell:

```powershell
ssh ubuntu@SERVER_PUBLIC_IP
```

На сервере Ubuntu 24.04:

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-v2 git
sudo systemctl enable --now docker
git clone https://github.com/swaggyt00/job-hunter-ai.git
cd job-hunter-ai
cp .env.example .env
chmod 600 .env
nano .env
```

Укажите внутри `.env` токен **того же** Telegram-бота и ваш `TELEGRAM_OWNER_ID`. Секреты нельзя добавлять в GitHub. Если токен потребуется отозвать из-за отсутствия доступа к Railway — делайте это через BotFather для **существующего** бота.

## 3. Сборка, не выключая старого бота

```bash
sudo docker compose build
```

Эта команда собирает Chromium и запускает модульные тесты через Dockerfile. Пока мы только собираем образ, старый бот остаётся живым.

## 4. Перенос истории

База прежней версии находится в томе Railway по адресу `/app/data/jobs.sqlite3`. Для корректной резервной копии работающей SQLite-базы используйте её backup API (например, `sqlite3 .backup`), а не слепое копирование при активном WAL. Результат нужно разместить в `./data/jobs.sqlite3` на новой VM.

**Без доступа к Railway-томy невозможно автоматически перенести сохранённые вакансии.** Если доступ так и не появится, новый бот может стартовать с пустой базой. **Не удаляйте старый том** до создания резервной копии.

## 5. Переключение Telegram

Две копии Telegram long polling с одним токеном одновременно запускать нельзя.

1. Если Railway доступен — остановите там старый процесс.
2. Если старый процесс остановить невозможно, отзовите его Telegram-токен через BotFather и используйте новый токен **того же бота** только в `.env` нового сервера. Имя и ссылка бота сохранятся.
3. Запустите:

```bash
mkdir -p data
sudo docker compose up -d
sudo docker compose ps
sudo docker compose logs --tail=100
```

4. В Telegram откройте того же бота и отправьте `/start` — должна появиться нижняя панель. Затем проверьте `/sources`, `/dream_scan` и `/hh_scan`.

Поиск HH останавливается при CAPTCHA / запросе логина — обхода проверок нет. Интерфейс для ручной авторизации в серверном Chromium пока не создан.

## 6. Обновления

```bash
git pull --ff-only
sudo docker compose up -d --build
```

Данные SQLite и профиль браузера хранятся в `./data/`, не внутри эфемерного контейнера. Наружу не публикуется ни один порт бота; он использует исходящие соединения.

Следите за маркировкой **Always Free** на VM, образе диска и регионе: установка оплачиваемых ресурсов может привести к списаниям.
